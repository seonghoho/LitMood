# 00. 제품 개요 — LitMood

## 한 줄 정의

> **읽고, 보고, 들은 것을 "그때의 기분"과 함께 기록하고 나누는 서비스.**

## 왜 만드는가 (Problem)

책은 왓챠피디아·북적북적, 영화는 왓챠·레터박스, 음악은 라스트에프엠·Spotify —
**콘텐츠 종류마다 기록 서비스가 흩어져 있다.** 사용자의 취향은 하나인데 기록은 세 곳에 분산된다.

또한 기존 서비스의 기록 단위는 대부분 **별점과 리뷰**다.
하지만 사람이 어떤 콘텐츠를 다시 떠올리는 계기는 평점이 아니라
"이거 그때 새벽에 들었던 곡인데", "시험 끝나고 몰아본 영화" 같은 **맥락과 감정**이다.

## 무엇이 다른가 (Differentiator)

|           | 기존 서비스          | LitMood                                                          |
| --------- | -------------------- | ---------------------------------------------------------------- |
| 대상      | 콘텐츠 종류별로 분리 | **책·영화·음악 통합 타임라인**                                   |
| 기록 단위 | 별점 + 리뷰          | 별점 + 리뷰 + **무드 태그 + 소비 맥락(언제/어디서/왜)**          |
| 탐색 축   | 장르, 인기순         | **무드 축** ("새벽", "비 오는 날", "번아웃")                     |
| 공유      | 리뷰 단건 공유       | **무드 컬렉션 공유** (여러 콘텐츠를 하나의 정서로 묶은 큐레이션) |

서비스명 `LitMood` = **Lit**erature/**Lit**(불 켜진) + **Mood**.
"기분에 불을 켠다"는 의미로, **무드가 이 서비스의 1급 개념(first-class concept)** 이다.

## 타깃 사용자

1. **기록형 사용자 (Primary)** — 소비한 콘텐츠를 남기는 게 습관인 사람. 흩어진 기록을 한곳에 모으고 싶다.
2. **큐레이터형 사용자 (Secondary)** — "비 오는 날 듣는 앨범 10선" 같은 리스트를 만들어 공유하고 싶은 사람.
3. **탐색형 사용자 (Tertiary)** — 지금 기분에 맞는 콘텐츠를 추천받고 싶은 사람. 초기엔 소비자로 유입되어 1·2번으로 전환된다.

## 핵심 사용자 여정 (Critical Path)

```
검색 → 콘텐츠 선택 → 기록 작성(상태·별점·무드·한줄) → 내 타임라인에 쌓임
                                                    ↓
                                        컬렉션으로 묶기 → 공개 → 타인이 발견
```

이 경로가 **막힘 없이 30초 안에** 끝나는 것이 MVP의 유일한 성공 기준이다.
추천·소셜·통계는 이 경로가 동작한 다음의 문제다.

## 성공 지표 (MVP)

| 지표                           | 목표  | 이유                     |
| ------------------------------ | ----- | ------------------------ |
| 가입 후 첫 기록까지 소요 시간  | < 3분 | 온보딩 마찰 측정         |
| 주간 기록 3건 이상 사용자 비율 | 30%   | 습관 형성 여부           |
| 기록당 무드 태그 부착률        | 60%   | 차별점이 실제로 쓰이는가 |
| 공개 기록 비율                 | 40%   | 공유 서비스로 성립하는가 |

## 명시적 비목표 (Non-goals)

MVP에서 **하지 않는 것**을 못 박아 둔다.

- ❌ 콘텐츠 원본 제공 (전문 열람, 스트리밍 재생) — 메타데이터와 기록만 다룬다
- ❌ ML 기반 개인화 추천 — 데이터가 쌓이기 전엔 무의미. 규칙 기반 추천으로 시작
- ❌ 실시간 채팅 / DM
- ❌ 모바일 네이티브 앱 — 반응형 웹(PWA)으로 대응
- ❌ 결제 / 유료 플랜
