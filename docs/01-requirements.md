# 01. 기능 명세

우선순위: **P0** = MVP 필수 / **P1** = MVP 직후 / **P2** = 이후

---

## F-01. 인증 / 계정

| ID      | 기능                                | 우선순위 | 상세                                                                  |
| ------- | ----------------------------------- | -------- | --------------------------------------------------------------------- |
| F-01-01 | 이메일 회원가입/로그인              | P0       | 비밀번호 bcrypt(cost 12). 이메일 인증은 P1                            |
| F-01-02 | OAuth2 소셜 로그인                  | P0       | Google, Kakao. 국내 타깃이므로 Kakao 필수                             |
| F-01-03 | JWT 세션                            | P0       | Access 15분(메모리) + Refresh 14일(HttpOnly·Secure·SameSite=Lax 쿠키) |
| F-01-04 | 프로필 (닉네임, 핸들, 소개, 아바타) | P0       | 핸들은 유니크, `@handle`로 공개 페이지 URL 구성                       |
| F-01-05 | 회원 탈퇴                           | P1       | Soft delete 후 30일 뒤 파기 (개인정보보호법 대응)                     |

**수용 기준 (F-01-03)**

- Access 토큰은 클라이언트 저장소(localStorage)에 두지 않는다 → XSS 시 탈취 방지
- Refresh 토큰은 Redis에 화이트리스트로 보관, 재발급 시 회전(rotation)
- 재사용 감지 시 해당 사용자의 전체 세션 무효화

## F-02. 콘텐츠 검색 / 조회

| ID      | 기능               | 우선순위 | 상세                                                              |
| ------- | ------------------ | -------- | ----------------------------------------------------------------- |
| F-02-01 | 통합 검색          | P0       | 하나의 검색창 → 책/영화/음악 탭 분리 결과                         |
| F-02-02 | 외부 API 연동      | P0       | 책: 네이버 책 / 영화: TMDB / 음악: Spotify                        |
| F-02-03 | 콘텐츠 상세        | P0       | 메타데이터 + 해당 콘텐츠의 공개 기록 목록 + 평균 별점 + 무드 분포 |
| F-02-04 | 검색 결과 캐싱     | P0       | Redis, TTL 6h. 외부 API rate limit 및 응답 지연 방어              |
| F-02-05 | 콘텐츠 로컬 영속화 | P0       | 기록이 처음 생성될 때 외부 콘텐츠를 자체 DB에 스냅샷 저장         |

**설계 원칙 (F-02-05)**
외부 API는 언제든 응답이 바뀌거나 항목이 사라진다.
**누군가 기록한 콘텐츠는 반드시 자체 DB에 복사본을 남긴다.** 그래야 외부 API가 죽어도 기록은 살아남는다.

**수용 기준 (F-02-02)**

- 외부 API 키는 **백엔드에만** 존재한다. 프론트엔드 번들에 절대 포함되지 않는다
- 세 provider의 응답은 백엔드에서 공통 `Content` 모델로 정규화된다 → 프론트는 provider를 모른다
- 한 provider가 실패해도 나머지 탭의 결과는 정상 반환한다 (부분 실패 허용)

## F-03. 기록 (Record) — 핵심 도메인

| ID      | 기능           | 우선순위 | 상세                                                                |
| ------- | -------------- | -------- | ------------------------------------------------------------------- |
| F-03-01 | 기록 생성      | P0       | 콘텐츠 + 상태 + 별점 + 무드 태그 + 한줄평                           |
| F-03-02 | 상태 관리      | P0       | `WANT`(보고싶다) / `DOING`(보는중) / `DONE`(다봄) / `DROPPED`(중단) |
| F-03-03 | 별점           | P0       | 0.5 ~ 5.0, 0.5 단위. **선택 사항** (별점 없이 무드만 기록 가능)     |
| F-03-04 | 무드 태그      | P0       | 사전 정의 태그 + 자유 입력. 기록당 최대 5개                         |
| F-03-05 | 한줄평 / 리뷰  | P0       | 최대 2,000자. 마크다운 미지원(P2)                                   |
| F-03-06 | 소비 맥락      | P1       | 시작일/종료일, 장소 메모, 재소비 횟수                               |
| F-03-07 | 공개 범위      | P0       | `PUBLIC` / `FOLLOWERS` / `PRIVATE`. 기본값은 사용자 설정 따름       |
| F-03-08 | 스포일러 처리  | P1       | 리뷰 블러 처리 플래그                                               |
| F-03-09 | 기록 수정/삭제 | P0       | 소유자만. 삭제는 soft delete                                        |

**제약**

- 한 사용자는 **한 콘텐츠에 대해 기록 1개**만 가진다 (`UNIQUE(user_id, content_id)`).
  재관람은 별도 기록이 아니라 `rewatch_count` 증가로 표현한다 → 타임라인 오염 방지

**수용 기준 (F-03-01)**

- 검색 결과에서 기록 작성까지 **화면 전환 없이** (모달/시트) 완료 가능
- 필수 입력은 `상태` 하나뿐. 나머지는 전부 선택 → 마찰 최소화

| ID      | 기능                  | 우선순위 | 상세                                      |
| ------- | --------------------- | -------- | ----------------------------------------- |

## 비기능 요구사항 (NFR)

| ID     | 항목          | 목표                                                              |
| ------ | ------------- | ----------------------------------------------------------------- |
| NFR-01 | 응답 시간     | 자체 DB 조회 API p95 < 300ms                                      |
| NFR-02 | 외부 API 의존 | 검색 p95 < 1.5s, 타임아웃 3s 후 부분 결과 반환                    |
| NFR-03 | 가용성        | 외부 API 장애 시에도 기록 조회/작성(기존 콘텐츠 대상)은 정상 동작 |
| NFR-04 | 보안          | 시크릿은 코드에 두지 않는다. 로컬 `.env`, 운영 K8s Secret         |
| NFR-05 | 접근성        | WCAG 2.1 AA. 키보드 내비게이션, 명도 대비 4.5:1                   |
| NFR-06 | SEO           | 공개 기록·컬렉션·프로필 페이지는 SSR + 구조화 데이터(JSON-LD)     |
| NFR-07 | 관측성        | 구조화 로그(JSON), `/actuator/health`, Prometheus 메트릭          |
| NFR-08 | 국제화        | 초기 ko-KR 단독. 문자열은 처음부터 외부화하여 확장 여지 확보      |
